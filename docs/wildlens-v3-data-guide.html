WildLens v2 — Spatial Data Guide

What to download · Where to get it · How to load into PostGIS  ·  Print: Ctrl+P → Save as PDF

Step 0 — Prerequisites (Do This Once)
0a
Find the PostGIS Shapefile Loader (already installed with PostGIS)
Since you already have PostgreSQL + PostGIS installed, the Shapefile Loader GUI is already on your machine. This is what you will use to upload all shapefiles — no command line needed.
Locate the Shapefile Loader on Windows
Click Start Menu → search for "PostGIS Shapefile" → open PostGIS Shapefile and DBF Loader Exporter.

If it does not appear in Start Menu, find it at:
C:\Program Files\PostgreSQL\16\bin\postgisgui\shp2pgsql-gui.exe
(replace 16 with your installed PostgreSQL version number — check Start Menu → PostgreSQL folder to see your version)
Connect the Loader to your wildlens database
1. In the Shapefile Loader window, click "View connection details…" at the top
2. Fill in the fields exactly:
  • Username: postgres
  • Password: [your postgres password]
  • Server Host: localhost   Port: 5432
  • Database: wildlens
3. Click OK
4. You will see "Connection succeeded" in the log at the bottom — if not, check that PostgreSQL is running (Start Menu → Services or pgAdmin sidebar should show it active)
0b
Create the database and enable extensions
PostGIS adds geometry types. pgvector adds vector embedding support for RAG. Both must be enabled before loading any spatial data.
Where to run these commands — pgAdmin 4 Query Tool
Open pgAdmin 4 (Start Menu → pgAdmin 4).
In the left panel, expand Servers → PostgreSQL → Databases.
Right-click postgres (the default database) → click "Query Tool".
Paste the commands below into the Query Tool editor and press F5 to run.
Step 1 — Create the wildlens database
Paste this into the Query Tool and press F5: 
CREATE DATABASE wildlens;
After it runs, you will see CREATE DATABASE in the Messages tab at the bottom.

Now in the left panel, right-click Databases → Refresh. You will see wildlens appear. Click it → right-click → Query Tool to open a new query window connected to the wildlens database.
Step 2 — Enable extensions (run inside the wildlens Query Tool)
Make sure the Query Tool tab says wildlens/postgres@PostgreSQL in its title. Then paste and press F5: 
CREATE EXTENSION postgis;
CREATE EXTENSION postgis_topology;
CREATE EXTENSION vector;
Each line returns CREATE EXTENSION in the Messages tab.
Step 3 — Verify extensions are active
In the same wildlens Query Tool, paste and press F5: 
SELECT PostGIS_version();
SELECT extname FROM pg_extension WHERE extname = 'vector';
First query returns a string like 3.4 USE_GEOS=1 USE_PROJ=1 ... — that means PostGIS is working.
Second query returns one row with vector — that means pgvector is active.

If the vector extension is missing: download pgvector for Windows from github.com/pgvector/pgvector → follow the Windows install instructions for your PostgreSQL version. Then re-run CREATE EXTENSION vector;.
Spatial Datasets — In Order of Priority
1
India Administrative Boundaries — States, Districts & Villages
Used for: enriching every event with stateProvince, county, and locality. Village-level gives the finest administrative resolution for pinpointing events inside forests where there may be no PA or corridor. Source: Census of India 2011 shapefiles — the authoritative legal administrative boundary dataset.
FREE — Census of India
Download — Census of India website
1. Go to censusindia.gov.in → Census 2011 → Maps → GIS Files (or navigate to the Census GIS portal directly)
2. Download three separate shapefile ZIPs:
  • STATE.zip — State boundaries (36 states + UTs)
  • DISTRICT.zip — District boundaries (~640 districts)
  • VILLAGE.zip — Village/Town boundaries (~640,000 polygons — large file, ~500MB zipped)
3. Unzip each. Each ZIP contains .shp, .dbf, .shx, .prj files — keep them all in the same folder.

Note on projection: Census shapefiles are usually in WGS84 (EPSG:4326) already, but always check the .prj file. If it says "GCS_WGS_1984" you are fine. If it says something else (e.g. Everest / Polyconic), add -s_srs EPSG:XXXX to the ogr2ogr command to re-project.
Load into PostGIS — using the Shapefile Loader GUI (repeat for each of the 3 files)
Do this once for STATE.shp, once for DISTRICT.shp, once for VILLAGE.shp. The steps are identical each time — only the filename and table name change.

In the PostGIS Shapefile and DBF Loader window (opened and connected in Step 0a):

1. Click "Add File" → browse to the folder where you unzipped the Census files → select STATE.shp → click Open
2. The file appears as a row in the table. Edit the row:
  • Schema: public
  • Table: type india_states (overwrite the auto-filled name)
  • Geo Column: wkb_geometry (leave default)
  • SRID: type 4326
  • Mode: Create
3. Click "Import". Watch the Log window at the bottom — it will say Shapefile type: Polygon then Done adding rows when finished.

4. Repeat for DISTRICT.shp → table name india_districts → Mode: Create
5. Repeat for VILLAGE.shp → table name india_villages → Mode: Create

Village import will take 10–20 minutes — 640,000 polygons. The Log window stays active while it runs. Do not close the Loader. You can open pgAdmin separately and run SELECT COUNT(*) FROM india_villages; to watch the row count climb.
Create spatial indexes — WHERE: pgAdmin 4 → wildlens Query Tool
Open pgAdmin 4. In the left panel expand Databases → wildlens → right-click → Query Tool. Paste the following and press F5: 
CREATE INDEX idx_india_states_geom    ON india_states    USING GIST (wkb_geometry);
CREATE INDEX idx_india_districts_geom ON india_districts USING GIST (wkb_geometry);
CREATE INDEX idx_india_villages_geom  ON india_villages  USING GIST (wkb_geometry);

CREATE INDEX idx_india_states_name    ON india_states    ("ST_NM");
CREATE INDEX idx_india_districts_name ON india_districts ("DISTRICT");
CREATE INDEX idx_india_villages_name  ON india_villages  ("VILLAGE");
Each statement returns CREATE INDEX in the Messages tab. The village geometry index takes a few minutes — that is normal. Do not skip it — without GIST index, spatial queries on 640k polygons will be very slow.
Verify — WHERE: pgAdmin 4 → wildlens Query Tool
In the same Query Tool, paste and press F5: 
-- Row counts (states ~36, districts ~640, villages ~640000)
SELECT 'states' AS layer, COUNT(*) FROM india_states
UNION ALL SELECT 'districts', COUNT(*) FROM india_districts
UNION ALL SELECT 'villages',  COUNT(*) FROM india_villages;

-- Spot check: should return Karnataka, Bangalore Urban, and a ward name
SELECT "ST_NM" FROM india_states    WHERE ST_Within(ST_SetSRID(ST_MakePoint(77.59, 12.97), 4326), wkb_geometry);
SELECT "DISTRICT" FROM india_districts WHERE ST_Within(ST_SetSRID(ST_MakePoint(77.59, 12.97), 4326), wkb_geometry);
SELECT "VILLAGE" FROM india_villages   WHERE ST_Within(ST_SetSRID(ST_MakePoint(77.59, 12.97), 4326), wkb_geometry);
Results appear in the Data Output tab below the editor.

2
WDPA — World Database of Protected Areas (India)
Used for: PA membership queries (is this event inside a PA?), nearestPA lookup, corridor connecting-PA attributes. Covers all 900+ Indian PAs with boundary polygons.
FREE — registration required
Download
1. Go to protectedplanet.net/en/thematic-areas/wdpa
2. Click "Download" → select country "India" → download as Shapefile
3. You get a ZIP with three folders: _0, _1, _2 (the data is split across them)
4. Each folder contains both polygon (-polygons.shp) and point (-points.shp) files

You want the polygon file from all three folders — most PAs have polygon boundaries. Points are used for PAs where only centroid is available.
Load into PostGIS — using the Shapefile Loader GUI (3 imports, all into the same table)
The WDPA download gives you three folders: _shp_0, _shp_1, _shp_2. Each folder has a -polygons.shp file. You load all three into the same table — first one creates the table, the next two append to it.

Import 1 — creates the table:
1. In the Shapefile Loader, click Add File → go into the _shp_0 folder → select the file ending in -polygons.shp → Open
2. Set the row: Table: wdpa_polygons  |  SRID: 4326  |  Mode: Create
3. Click Import — wait for "Done adding rows" in the Log

Import 2 — appends to the same table:
1. Click Add File → go into the _shp_1 folder → select the -polygons.shp file → Open
2. Set: Table: wdpa_polygons  |  SRID: 4326  |  Mode: Append ← important, must be Append not Create
3. Click Import

Import 3 — appends again:
Same as Import 2 but using the _shp_2 folder's -polygons.shp file. Mode: Append.
India-only WDPA is ~30 MB across all three folders. Each import is fast (under a minute).
Create spatial index + verify — WHERE: pgAdmin 4 → wildlens Query Tool
Open pgAdmin 4 → wildlens database → Query Tool. Paste and press F5:

4
Corridor Metadata — 3 Public Government PDFs (no shapefile request needed)
Used for: corridor membership (wildlens:corridorName), corridor stress index, pinch-point analysis. All three source documents are publicly available. Two-track approach: (1) structured text extraction → PostgreSQL metadata table; (2) Phase 1 polygon geometry = WDPA convex hull between connecting PA pairs; Phase 2 = manual QGIS digitizing.
FREE — 3 public PDFs, no data agreement needed
Source documents
Download all three — all publicly available from government/NGO websites:

1. MoEF 2023 Elephant Corridor Report — moef.gov.in (search "elephant corridor 2023"). 101 corridors with names, states, status, connecting PAs, threat assessment.

2. WTI "Right of Passage" 2005 — wti.org.in (publications section). Corridor polygons described as WDPA polygon pairs. Corridor status, width at narrowest, species using corridor.

3. WII Tiger Status & Co-Predators Report 2022 — v1.wii.gov.in. Tiger corridor linkages between reserves; overlaps significantly with elephant corridors.
Track 1 — Extract structured metadata with pdfplumber
Goal: Pull corridor name, state, width, connecting PAs, threat status into a PostgreSQL table.

import pdfplumber

def extract_corridor_table(pdf_path):
    rows = []
    with pdfplumber.open(pdf_path) as pdf:
        for page in pdf.pages:
            tables = page.extract_tables()
            for table in tables:
                for row in table:
                    if row and len(row) >= 4:
                        rows.append(row)
    return rows
Not all content is in tables — some corridors described in prose. Use regex fallback to extract corridor names from text paragraphs: r'(?:corridor|passage)[:\s]+([A-Z][a-z ]+(?:–[A-Z][a-z ]+)?)'. After extraction, create corridors table: corridor_id, name, state, width_m, status, connecting_pa_1, connecting_pa_2, threat_description, source_doc.
Track 2 — Phase 1 geometry: WDPA convex hull between connecting PA pairs
Once corridor metadata table is populated with connecting_pa_1 and connecting_pa_2, generate Phase 1 geometry automatically:

-- Phase 1: approximate corridor geometry from WDPA polygon pair convex hull
-- Replace manually later in Phase 2 with QGIS-digitized polygons
INSERT INTO corridor_geometries (corridor_id, geom, method)
SELECT
  c.corridor_id,
  ST_ConvexHull(ST_Union(w1.wkb_geometry, w2.wkb_geometry)) AS geom,
  'wdpa_convex_hull' AS method
FROM corridors c
JOIN wdpa_polygons w1 ON w1.name ILIKE '%' || c.connecting_pa_1 || '%'
JOIN wdpa_polygons w2 ON w2.name ILIKE '%' || c.connecting_pa_2 || '%';
Convex hull between two PA polygons overestimates corridor area — it includes land between the PAs regardless of actual connectivity. Acceptable for Phase 1 membership queries. Replace with hand-digitized polygon in Phase 2 using QGIS.
Track 3 — Index PDFs into pgvector for RAG queries
import pdfplumber
from sentence_transformers import SentenceTransformer

model = SentenceTransformer('all-MiniLM-L6-v2')

def index_pdf_for_rag(pdf_path, source_doc):
    chunks = []
    with pdfplumber.open(pdf_path) as pdf:
        text = ' '.join(p.extract_text() or '' for p in pdf.pages)
    # Chunk by ~500 chars at sentence boundaries
    sentences = text.split('. ')
    chunk = ''
    for s in sentences:
        if len(chunk) + len(s) > 500:
            chunks.append(chunk.strip())
            chunk = s
        else:
            chunk += '. ' + s
    if chunk:
        chunks.append(chunk.strip())
    embeddings = model.encode(chunks)
    return list(zip(chunks, embeddings))
Store results in the research_papers table (document_type='report').

5
GFW — Global Forest Watch Forest Cover & Alerts
Used for: annual forest cover loss per PA/corridor, deforestation alerts (GLAD/RADD), loss by driver, corridor width computation. This is raster data — not loaded into PostGIS as polygons. Queried via GFW REST API or downloaded as GeoTIFF.
FREE — register at globalforestwatch.org
Two ways to use GFW — choose based on what you need
Option A — GFW REST API (recommended for annual summaries):
POST your PA/corridor polygon as GeoJSON → get back annual loss data as JSON. No file download needed. Results stored in PostgreSQL as a time series per polygon.

Option B — GeoTIFF download (needed for corridor width computation):
Download the Hansen tree cover loss raster tile for India (30m resolution) → analyse locally with rasterio → compute patch statistics.
Option A — GFW API setup
1. Register at globalforestwatch.org → API key (free, annual renewal)
2. Set key as environment variable: GFW_API_KEY=your_key
3. For each PA polygon in wdpa_polygons, POST to GFW and store result: 
import requests, json

def query_gfw(geojson_polygon, api_key):
    url = "https://data-api.globalforestwatch.org/dataset/umd_tree_cover_loss/latest/query"
    payload = {
        "geometry": geojson_polygon,
        "sql": """SELECT umd_tree_cover_loss__year,
                         SUM(area__ha) AS loss_ha,
                         SUM(umd_tree_cover_loss__year) AS count
                  FROM data
                  WHERE umd_tree_cover_density_2000__threshold = 30
                  GROUP BY umd_tree_cover_loss__year
                  ORDER BY umd_tree_cover_loss__year"""
    }
    r = requests.post(url, json=payload,
                      headers={"x-api-key": api_key})
    return r.json()["data"]
Results go into the forest_cover table in PostgreSQL (polygon_id, year, loss_ha).
Option B — GeoTIFF download for raster analysis
1. Go to earthenginepartners.appspot.com/science-2013-global-forest → Download tiles
2. India spans tiles: 20N_080E, 20N_070E, 30N_080E, 30N_070E, 10N_080E, 10N_070E
3. Download the lossyear band GeoTIFF for each tile (~200MB each)
4. Merge tiles with GDAL: 
gdal_merge.py -o india_lossyear.tif \
  Hansen_GFC-2023-v1.11_lossyear_20N_080E.tif \
  Hansen_GFC-2023-v1.11_lossyear_20N_070E.tif \
  Hansen_GFC-2023-v1.11_lossyear_30N_080E.tif \
  Hansen_GFC-2023-v1.11_lossyear_30N_070E.tif \
  Hansen_GFC-2023-v1.11_lossyear_10N_080E.tif \
  Hansen_GFC-2023-v1.11_lossyear_10N_070E.tif
5. Keep the merged GeoTIFF as a file — analyse with rasterio (clip to corridor polygon, compute width). Do NOT load into PostGIS unless you need spatial queries on the raster.
Merged India raster is ~1.2GB. Keep as a file on your local machine — do not load into PostgreSQL.
6
FSI Forest Cover Boundary — Fire Classification Layer 1
Used for: five-layer fire classification (Layer 1). Any fire inside this boundary → FOREST_FIRE. The authoritative government definition of forest cover in India. Must use FSI ISFR, not GFW, for the L1 classification — GFW uses a different tree cover definition.
FREE — FSI Website
Download
1. Go to fsi.nic.in → Publications → India State of Forests Report (ISFR 2021 or latest)
2. GIS data link is usually on the ISFR page — download the forest cover shapefile (two density classes: Very Dense Forest + Moderately Dense Forest + Open Forest)
3. If FSI shapefile link is unavailable, use ISRO Bhuvan (bhuvan.nrsc.gov.in) → Thematic Services → Vegetation/Land Cover → National Forest Cover
4. For fire classification: use Very Dense + Moderately Dense + Open Forest classes combined as a single forest cover mask
⚠ FSI updates ISFR every 2 years. Always use the most recent edition. Note the survey year so fire events can be matched to the correct cover version.
Load into PostGIS
In the Shapefile Loader: Table: fsi_forest_cover  |  SRID: 4326  |  Mode: Create

After loading: 
CREATE INDEX idx_fsi_geom ON fsi_forest_cover USING GIST (wkb_geometry);

-- Fire in forest? (Layer 1 check)
SELECT COUNT(*) FROM fsi_forest_cover
WHERE ST_Intersects(
  ST_SetSRID(ST_MakePoint(:fire_lon, :fire_lat), 4326),
  wkb_geometry
);
If count > 0 → classify as FOREST_FIRE. Stop classification — do not check further layers.

Open Natural Ecosystems (ONE) Boundary — Fire Classification Layer 2
Used for: fire classification Layer 2 (ONE_FIRE). Grasslands, savannas, shola edges, scrublands, rocky outcrops. These are ecologically primary habitats — NOT wastelands. Fires in ONE are routinely set for land conversion (solar farms, plantations). Cross-check IUCN ranges for GIB, blackbuck, wolf, florican.
Email NCF / ATREE — pending data agreement
How to get the shapefile
Primary source (email both):
1. Nature Conservation Foundation (NCF) — ncf-india.org. Ask for the ONE/open ecosystem boundary shapefile. Abi Vanak's group has published extensively on this.
2. ATREE (Ashoka Trust for Research in Ecology and the Environment) — atree.org. Abi Vanak's lab directly. Reference: Vanak et al. publications on open natural ecosystems in India.

Interim approach while waiting for NCF/ATREE:
Derive from MODIS MCD12Q1 (annual land cover, free NASA Earthdata): 
# Combine MODIS classes that approximate ONE extent
# Class 8 = Woody Savanna, 9 = Savanna, 10 = Grassland
# 12 = Cropland excluded, 14 = Cropland/Natural Vegetation mosaic excluded
# Then subtract FSI forest cover boundary
# Result = approximate ONE extent

import rasterio
import numpy as np

with rasterio.open('MCD12Q1.A2022001.india.tif') as src:
    lc = src.read(1)
    # ONE proxy: savanna + grassland classes
    one_mask = np.isin(lc, [8, 9, 10])
    profile = src.profile
MODIS-derived ONE is approximate — it misclassifies some shola edges and scrublands. Use as interim only. NCF/ATREE shapefile is the publication-grade layer.

8
Agriculture Extent — Fire Classification Layer 3
Used for: fire classification Layer 3. Oct–Nov fires in Indo-Gangetic Plain = AGRICULTURAL_STUBBLE (exclude from system). Off-season fires in agricultural land = AGRICULTURAL_SUSPICIOUS (retain). Seasonal filter is critical — October–November IGP fires are one of the most common false positive triggers.
FREE — ISRO Bhuvan + MODIS
Data sources
Option A (best spatial resolution): ISRO Bhuvan → bhuvan.nrsc.gov.in → Thematic Services → Crop/Agriculture layer. WMS service — can query per point without downloading full raster.

Option B (easiest for Python): MODIS MCD12Q1 annual land cover (free from NASA Earthdata). Class 12 = Cropland, Class 14 = Cropland/Natural Vegetation mosaic. Download the India tile, load as raster.

Seasonal filter logic: 
# Apply to every fire before classifying as agricultural
def is_stubble_burning(fire_date, fire_lat, fire_lon, igp_polygon):
    """
    Oct 1 - Nov 30 + inside Indo-Gangetic Plain = stubble burning
    IGP approximate bbox: lat 20–32, lon 72–89
    """
    month = fire_date.month
    in_igp = igp_polygon.contains(Point(fire_lon, fire_lat))
    return month in [10, 11] and in_igp

NRSC Wasteland Atlas 2019 — Fire Classification Layer 4
Used for: fire classification Layer 4 cross-check. Many ecologically significant habitats (grasslands, scrublands, wetland margins, shola edges) are legally classified as "wasteland" in India. Do NOT dismiss fires in wasteland as low priority without first cross-checking IUCN ranges. If inside any species range → treat same as ONE_FIRE.

ESA CCI Biomass — Above-Ground Biomass for Fire Loss Calculation
Used for: calculating biomass lost in FOREST_FIRE and ONE_FIRE events. Formula: burned area (ha) × biomass density at that location (t/ha) = biomass lost (tonnes). This is the novel quantitative output for fire events — "Fire at [location] destroyed approximately X ha, estimated Y tonnes biomass lost."
FREE — ESA Climate Change Initiative
Download
1. Go to climate.esa.int/en/projects/biomass/ → Data → Download
2. Select: ESA CCI Biomass Version 5 — Above-Ground Biomass (100m resolution, global)
3. Download the South Asia tiles covering India (~2GB total)

Alternative — Spawn et al. 2020: "Harmonized global maps of above and belowground biomass carbon density" — available via NASA EarthData at 300m resolution. Smaller download, slightly coarser.
Usage — biomass loss calculation
import rasterio
from rasterio.mask import mask
from shapely.geometry import mapping
import numpy as np

def calc_biomass_loss(burned_polygon, biomass_raster_path):
    """
    burned_polygon: Shapely polygon of burned area (from MODIS MCD64A1)
    Returns: biomass lost in tonnes
    """
    with rasterio.open(biomass_raster_path) as src:
        out_image, _ = mask(src, [mapping(burned_polygon)], crop=True)
        # Pixel values = above-ground biomass in tonnes/ha
        biomass_density = out_image[0]
        biomass_density[biomass_density < 0] = 0  # no-data mask

    pixel_area_ha = (src.res[0] * 111320) ** 2 / 10000  # degrees to ha at India latitude
    total_biomass = np.sum(biomass_density) * pixel_area_ha
    return round(total_biomass, 1)
Store result in forest_fire_events.biomass_lost_tonnes.
Sentinel-2 burned area required for fires <1 ha — MODIS MCD64A1 (500m) cannot detect small fires. Flag limitation in output metadata when fire area is <25 ha.

NASA FIRMS — Active Fire Alerts (Real-Time)
Used for: detecting active fires within 3–6 hours of occurrence. MODIS + VIIRS sensors. For each active fire alert: run through the five-layer classification pipeline immediately. FOREST_FIRE and ONE_FIRE trigger alert emails. Feeds forest_fire_events table in real time.
FREE — NASA Earthdata account required
Setup
1. Register at earthdata.nasa.gov → free account
2. Go to firms.modaps.eosdis.nasa.gov/api → register for a FIRMS MAP_KEY (also free)
3. Install: pip install requests
Polling active fires for India
import requests

FIRMS_KEY = "your_map_key"
INDIA_BBOX = "68,6,98,37"  # lon_min,lat_min,lon_max,lat_max

def get_active_fires(days=1, source='VIIRS_SNPP_NRT'):
    """Get active fire detections for India in last N days"""
    url = (f"https://firms.modaps.eosdis.nasa.gov/api/area/csv/"
           f"{FIRMS_KEY}/{source}/{INDIA_BBOX}/{days}")
    resp = requests.get(url, timeout=30)
    lines = resp.text.strip().split('\n')
    if len(lines) < 2:
        return []
    header = lines[0].split(',')
    fires = []
    for line in lines[1:]:
        row = dict(zip(header, line.split(',')))
        fires.append({
            'lat': float(row['latitude']),
            'lon': float(row['longitude']),
            'acq_date': row['acq_date'],
            'confidence': row['confidence'],
            'bright_t31': float(row.get('bright_t31', 0)),
            'source': source
        })
    return fires

# Run classification pipeline on each fire point
for fire in get_active_fires(days=1):
    classify_fire(fire['lat'], fire['lon'], fire['acq_date'])
Run this as a scheduled GitHub Actions workflow (daily or 6-hourly). Classify each fire through the 5-layer pipeline and insert into forest_fire_events table.

SDM Environmental Predictors — WorldPop · OSM · MODIS Night-Lights · KBDI
Used for: Conflict Risk SDM (Phase 4). Two-axis classification: Axis 1 Resource Suitability (IUCN range + GFW + PA proximity + EVI + KBDI drought) × Axis 2 Human Pressure (WorldPop + OSM roads + night-lights + PA distance). All layers needed before running biomd2 ensemble.
FREE — multiple sources
WorldPop India population grid (100m)
1. Go to worldpop.org → Data → Population → India → 100m resolution → 2020 (or latest year)
2. Download India_ppp_2020_constrained.tif (~200MB)
3. Keep as GeoTIFF file — do not load into PostgreSQL. Query per SDM occurrence point with rasterio.
4. For SDM: extract population density value at each occurrence point (elephant HWC, etc.) as Axis 2 predictor.
OSM road network (geofabrik.de)
1. Go to download.geofabrik.de → Asia → India → india-latest.osm.pbf
2. Extract roads with osmium: osmium tags-filter india-latest.osm.pbf w/highway -o india_roads.osm.pbf
3. Convert to shapefile: ogr2ogr -f "ESRI Shapefile" india_roads.shp india_roads.osm.pbf lines
4. Load into PostGIS: Table: osm_roads  |  SRID: 4326
5. For SDM: compute ST_Distance from each occurrence point to nearest road (Axis 2 — Human Pressure predictor). 
CREATE INDEX idx_osm_roads_geom ON osm_roads USING GIST (wkb_geometry);

-- Distance to nearest road (metres)
SELECT ST_Distance(
  wkb_geometry::geography,
  ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography
) AS dist_m
FROM osm_roads
ORDER BY wkb_geometry <-> ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)
LIMIT 1;
MODIS nighttime lights (DMSP + VIIRS intercalibrated)
1. Download VIIRS Night-Time Lights (VNP46A2) from NASA Earthdata — Monthly composite, 500m
2. DMSP-OLS historical (pre-2012) — available from NOAA National Centers for Environmental Information
3. For continuous 2000–present time series: use Shao et al. 2014 or Li et al. 2017 intercalibrated DMSP+VIIRS dataset (check latest intercalibration publication)
4. Keep as annual GeoTIFF — extract per occurrence point with rasterio (Axis 2 — Human Pressure proxy for market access / demand centres).
EVI from MODIS MOD09A1 (vegetation index — resource suitability)
1. Use Google Earth Engine (free tier) to export monthly EVI composites for India 2000–present
2. Or download MODIS MOD09A1 tiles from NASA Earthdata and compute EVI: EVI = 2.5 × (NIR - Red) / (NIR + 6×Red - 7.5×Blue + 1)
3. Compute monthly median, gap-fill with 10-year climatological average for each pixel
4. Match each occurrence point to EVI value from same month + year (time-calibration as per Kitratporn & Takeuchi 2020 — Axis 1 predictor).
Core PostGIS Queries Used by the Pipeline
Q
Queries the pipeline runs automatically against these layers
Every event that enters the system gets enriched by these queries. These are reference queries — the Python pipeline will run them programmatically. You can test any of them manually in pgAdmin 4 → wildlens Query Tool by replacing :lat/:lon with real coordinates and pressing F5.
1 — Is the event inside a PA? Which one?
SELECT name, desig, gis_area
FROM wdpa_polygons
WHERE ST_Within(
  ST_SetSRID(ST_MakePoint(:lon, :lat), 4326),
  wkb_geometry
)
LIMIT 1;
Returns wildlens:paName and wildlens:paType. If no result: event is outside a PA.
2 — Nearest PA within 5km (for events just outside PA boundary)
SELECT name, desig,
       ST_Distance(wkb_geometry::geography,
                   ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography) / 1000 AS dist_km
FROM wdpa_polygons
ORDER BY wkb_geometry <-> ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)
LIMIT 1;
Returns wildlens:nearestPAName and wildlens:nearestPADistKm.
3 — Which corridor does the event fall in?
SELECT corridor_name, state, status, intensity_of_use
FROM wti_corridors
WHERE ST_Within(
  ST_SetSRID(ST_MakePoint(:lon, :lat), 4326),
  wkb_geometry
)
LIMIT 1;
Returns wildlens:corridorName. Null if event is not inside a mapped corridor.
4 — State, district and village enrichment (Census columns)
-- State → stateProvince
SELECT "ST_NM" AS state FROM india_states
WHERE ST_Within(ST_SetSRID(ST_MakePoint(:lon, :lat), 4326), wkb_geometry);

-- District → county
SELECT "DISTRICT" AS district, "ST_NM" AS state FROM india_districts
WHERE ST_Within(ST_SetSRID(ST_MakePoint(:lon, :lat), 4326), wkb_geometry);

-- Village → locality (finest resolution — useful inside forest areas)
SELECT "VILLAGE" AS village, "SUBDIST" AS subdistrict,
       "DISTRICT" AS district FROM india_villages
WHERE ST_Within(ST_SetSRID(ST_MakePoint(:lon, :lat), 4326), wkb_geometry);
Returns stateProvince, county, and locality for the event schema. Village query may return null for uninhabited forest areas — that is expected and fine.
5 — Toponym disambiguation: does location overlap species range?
-- Score two candidate locations for a tiger article
-- Higher intersection area = more ecologically plausible location
SELECT sci_name,
       ST_Area(ST_Intersection(
         wkb_geometry,
         ST_Buffer(ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography, 50000)::geometry
       )) AS overlap_score
FROM iucn_ranges
WHERE sci_name = :species_sci_name
AND presence = 1
AND origin = 1
AND ST_DWithin(wkb_geometry::geography,
               ST_SetSRID(ST_MakePoint(:lon, :lat), 4326)::geography,
               50000);
Run this for each NER candidate location. Pick the candidate with highest overlap_score.
